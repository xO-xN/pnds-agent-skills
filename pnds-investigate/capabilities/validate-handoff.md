# Validate, distribute and hand off / 分阶段验证与交接

Input: an initial or existing project, decisions and desired delivery scope; optional explicit distribution task. Output: editable source, actual validation ledger, remaining tasks; a .pnds plus SHA256 only when requested or required by the explicitly selected CM1 course workflow. Done: delivered artifacts and claims match observed evidence.

Read [platform-sources](../reference/platform-sources.md), [records](../reference/records.md) and [tools](../reference/tools.md). Use the project's own checks and new behavior tests for changed logic. Record each stage independently: static structure; actual creation-mode open; wiring; automated checks; runtime health and shutdown; real browser cold/warm rendering; audio/devices; performance; bundle and installation. Record commands/actions, input revision, corpus/App/module versions, harness/model and limitations. Unknown, blocked and not-run results are not passing results.

A structurally complete initial project may return to App creation mode with sound/runtime still pending. Preserve completed work rather than starting over. None-mode ready is not proof of Internal/External, visual rendering, phone input or performance acceptance. Browser screenshots cannot prove real multitouch or sound. Only observed native operations prove App embedding/opening; App development server is started by the user.

Default ordinary tasks to editable source plus decisions, validation and handoff. Do not package just because the project can be opened. For explicit distribution, follow the matched bundle contract: saved disk inputs, complete production dependencies, all declared compiled audio artifacts, containment, permissions, root layout, exclusions and safe external output. No unrequested install/build/npm actions. Prefer installed App packaging; the bundled static helper is available with its declared limitations. Validate archive content and SHA256, and record installation round trip separately. Content changes to a previously distributed project need a version increment; preserve id.

Hand off concrete paths, operation flow, completed/pending checks and acceptance steps. Keep source records out of manifest runtime fields. Preserve current creator tasks; update only actual completed work. If resources, tools or device conditions are unavailable, deliver useful source/progress with precise restrictions. Never mark unrun distribution or audio checks as passed.
