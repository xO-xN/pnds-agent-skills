# Adapt runtime / 运行契约与创作初版

Input: confirmed implementation plan or a requested contract audit, source/new project destination and target App/corpus evidence. Output: contract findings, or a complete editable initial project with records. Done for an initial version: necessary structure is complete and creation-mode opening conditions are met; actual App opening is recorded only after observed.

Read [platform-sources](../reference/platform-sources.md), then the matched manifest, structure, runtime, audio, network and page contracts. Read [records](../reference/records.md). An audit-only invocation reports findings without implementing. Implementation follows the author's confirmed artistic/deployment choices.

Prepare manifest and declared server entry/working directory, actual performer and monitor assets, necessary dependencies and any confirmed audio assets. Validate declared path containment, production dependencies, audio mode rules, health identity/ports, audio bus ownership and graceful shutdown against the matched manual. Runtime cannot depend on installed system Node/sclang or undeclared sibling projects. Do not invent Host fields, audio modes or bundle formats.

For new work choose identity and defaults from the plan; use a discoverable, versioned starter only where needed. Strip the starter's artistic examples instead of shipping their sounds, control policies or score as the author's work. For existing PNDS work preserve identity, token/storage namespaces, author code, compatibility strategies and decisions; change only what the adaptation requires.

Deliver the editable project when structural conditions are complete. If the App has not actually opened it, report “structure checked; creation-mode opening not yet verified”. Keep structure, wiring, health, sound, performance and distributability separate. Missing compiler/audio/device/runtime conditions do not require regenerating the initial source, but block corresponding startup/distribution claims. None-mode smoke is optional, explicit execution and proves only that mode. Continue with [validate/handoff](validate-handoff.md) for staged evidence.
